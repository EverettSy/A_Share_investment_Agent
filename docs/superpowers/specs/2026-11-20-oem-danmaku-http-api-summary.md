## 一、接口清单（完整 API 列表）

### 1. 代理商需要提供的接口（3个）

#### 1.1 开始监听接口
- **提供方**: 代理商
- **调用方**: 平台方
- **功能**: 开始监听直播间弹幕
- **方法**: `POST`
- **路径**: `/api/open/tasks`
- **完整示例URL**: `https://agent.example.com/api/open/tasks`

**请求参数**:
| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `live_auth_code` | string (1-128字符) | 是 | 本次开播唯一标识码 |
| `live_url` | string (最大2048字符) | 是 | 需要监听的直播间地址（如抖音直播链接） |

**请求示例**:
```json
{
  "live_auth_code": "live_demo_20261120_000001",
  "live_url": "https://live.douyin.com/123456789012"
}
```

**成功响应示例**:
```json
{
  "code": 1,
  "msg": "监听成功"
}
```

**异常处理**:
- 直播间不存在或未开播: 返回 HTTP 200, `code=0`, 并在 `msg` 中说明原因
- 临时连接失败: 返回 HTTP 503, `code=0`

#### 1.2 停止监听接口
- **提供方**: 代理商
- **调用方**: 平台方
- **功能**: 停止监听指定直播间
- **方法**: `POST`
- **路径**: `/api/open/tasks/stop`
- **完整示例URL**: `https://agent.example.com/api/open/tasks/stop`

**请求参数**:
| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `live_auth_code` | string (1-128字符) | 是 | 需要停止的直播间标识码 |

**请求示例**:
```json
{
  "live_auth_code": "live_demo_20261120_000001"
}
```

**成功响应示例**:
```json
{
  "code": 1,
  "msg": "停止成功"
}
```

**行为要求**:
- 持久化停止标记
- 同步返回前终止订阅并清理待发送普通弹幕

#### 1.3 同步重连接口
- **提供方**: 代理商
- **调用方**: 平台方
- **功能**: 在收到 status="-2" 系统通知后重新建立监听
- **方法**: `POST`
- **路径**: `/api/open/tasks/reconnect`
- **完整示例URL**: `https://agent.example.com/api/open/tasks/reconnect`

**请求参数**:
| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `live_auth_code` | string (1-128字符) | 是 | 直播间标识码 |
| `request_id` | string | 是 | 重连操作唯一ID（使用触发重连的系统通知的 msg_id） |

**成功响应示例**:
```json
{
  "code": 1,
  "msg": "重连成功"
}
```

## 二、数据字段详细定义

### 2.1 通用字段（标识与格式）

| 字段名 | 含义 | 详细说明 |
|--------|------|----------|
| `live_auth_code` | 本次开播唯一码 | 每次开播都会刷新，在整个直播期间保持不变，永不复用。代理商需原样返回。 |
| `live_url` | 直播间地址 | 完整的可监听直播间URL（支持原平台或三方分享链接），不含分享文案 |
| `live_id` | 源平台房间ID | 源平台（如抖音/快手）的直播间ID，非平台内部开播位ID |
| `msg_id` | 事件唯一ID | 系统通知必填，普通弹幕可选（用于去重）。重试时保持不变 |
| `request_id` | 单次操作ID | 用于重连操作。系统通知重连时使用通知的 msg_id 作为 request_id |
| `recv_time` | 接收时间戳 | Unix毫秒时间戳，代理商首次收到事件的时间，重试时不变 |

### 2.2 普通弹幕字段

**comments 数组中的单个弹幕对象**:

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `live_id` | string (1-128字符) | 是 | 源平台直播间ID |
| `nickname` | string (最大128字符) | 否 | 原始昵称，源服务未提供时可为空 |
| `msg_type` | string | 是 | 消息类型：`msg`(评论)、`come`(进入房间)、`follow`(关注)、`like`(点赞)、`gift`(礼物) |
| `live_auth_code` | string (1-128字符) | 是 | 开播任务时使用的 code |
| `message` | string (最大2000字符) | 条件必填 | 原始评论或事件描述。msg_type为msg时必填 |
| `recv_time` | integer | 是 | 毫秒时间戳，代理商首次收到时间，重试时不变 |
| `msg_id` | string (1-128字符) | 否 | 可选，稳定消息ID，重试时不变 |

**普通弹幕请求示例**:
```json
{
  "comments": [
    {
      "live_id": "123456789012",
      "nickname": "小明",
      "msg_type": "msg",
      "live_auth_code": "live_demo_20261120_000001",
      "message": "这个怎么购买？",
      "recv_time": 1795132801000
    },
    {
      "live_id": "123456789012",
      "nickname": "小红",
      "msg_type": "come",
      "live_auth_code": "live_demo_20261120_000001",
      "message": "",
      "recv_time": 1795132801200
    }
  ]
}
```

### 2.3 系统通知字段

**当 msg_type="sys" 时的字段定义**:

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `msg_type` | string | 是 | 固定值: `sys` |
| `status` | string | 是 | `-1`: 停止监听<br>`-2`: 请求重新连接 |
| `live_auth_code` | string (1-128字符) | 是 | 对应的开播码 |
| `message` | string (1-2000字符) | 是 | 异常原因（如"直播间已关播"、"监听连接断开"） |
| `recv_time` | integer | 是 | 毫秒时间戳 |
| `msg_id` | string (1-128字符) | 是 | 系统事件唯一ID，重试时不变，用于防重复 |
| `live_id` | string (最大128字符) | 否 | 源平台房间ID（解析失败时可为空） |
| `nickname` | string (最大128字符) | 否 | 系统通知不需要，可为空 |

#### 系统通知示例

**停止通知 (status="-1")**:
```json
{
  "comments": [
    {
      "msg_type": "sys",
      "status": "-1",
      "live_auth_code": "live_demo_20261120_000001",
      "message": "直播间已关播，停止监听",
      "recv_time": 1795132810000,
      "msg_id": "sys-stop-001"
    }
  ]
}
```

**重连通知 (status="-2")**:
```json
{
  "comments": [
    {
      "msg_type": "sys",
      "status": "-2",
      "live_auth_code": "live_demo_20261120_000001",
      "message": "监听连接断开，请重新连接",
      "recv_time": 1795132805000,
      "msg_id": "sys-reconnect-001"
    }
  ]
}
```

### 2.4 status 状态码行为说明

| status | 代理商行为 | 平台方（我方）行为 |
|--------|------------|-------------------|
| `-1` | 直播间已关播、不存在或确认不可继续时，立即停止本 code 的监听并保存终态，再上报 | 标记本 code 的监听已终止，停止处理其弹幕，取消待重连；必要时调用停止接口确认清理，不再自动重连 |
| `-2` | 暂时断线等可恢复异常时，暂停故障订阅并上报，保留任务；等待我方重连命令，不同时自行启动另一轮重连 | 确认本次开播仍有效且监听未终止后，保存重连待办，调用代理商同步重连接口；request_id 使用本条 msg_id |

## 三、通用约定

### 3.1 数据格式
- **编码**: UTF-8
- **格式**: JSON
- **字段名**: 区分大小写
- **必需请求头**:
  ```
  Content-Type: application/json; charset=utf-8
  Accept: application/json
  ```

### 3.2 数据类型约定
- `status`: 字符串类型（如 "-1", "-2"）
- `code`: 数字类型（1 表示成功，0 表示失败）
- `recv_time`: Unix 毫秒时间戳

### 3.3 IP 白名单鉴权

**双向 IP 白名单机制**:

1. **平台调用代理商**:
   - 代理商需要将平台方任务提交服务器的固定公网出口IP加入白名单

2. **代理商回调平台**:
   - 平台方需要将代理商回调服务器的固定公网出口IP加入白名单

### 3.4 统一响应格式

**所有业务结果使用统一 code**:
- HTTP 状态码: 正常处理时均为 `200`
- `code: 1`: 成功，或重复请求已完成，或晚到事件已忽略（不要重新提交）
- `code: 0`: 失败，原因在 `msg` 字段中（根据配置和请求内容排查，勿将 msg 作为程序逻辑分支依据）

**成功响应示例**:
```json
{
  "code": 1,
  "msg": "ok"
}
```

**失败响应示例**:
```json
{
  "code": 0,
  "msg": "直播间不存在"
}
```

## 四、完整业务流程

### 4.1 初始化流程

```
用户 → 开播
  ↓
平台服务器 → POST /api/open/tasks (代理商)
  参数: live_auth_code, live_url
  ↓
代理商监听服务 → 建立直播间监听
  ↓
代理商监听服务 → 返回 {code: 1, msg: "监听成功"}
```

### 4.2 弹幕推送流程

```
[循环: 收到弹幕]
代理商监听服务 → POST /api/partner/danmaku/comments (平台)
  参数: comments 数组（普通弹幕）
  ↓
平台服务器 → 返回 {code: 1, msg: "已接收"}
```

### 4.3 异常重连流程

```
[可选: 监听异常且可以重连]
代理商监听服务 → POST /api/partner/danmaku/comments (平台)
  参数: msg_type=sys, status=-2
  ↓
平台服务器 → 保存系统事件及待重连任务
  ↓
平台服务器 → 返回 {code: 1, msg: "已接收"}
  ↓
平台服务器 → POST /api/open/tasks/reconnect (代理商)
  参数: live_auth_code, request_id
  ↓
代理商监听服务 → 重新建立监听
  ↓
代理商监听服务 → 返回 {code: 1, msg: "重连成功"}
```

### 4.4 停止流程

```
[可选: 直播间已下播或不存在]
代理商监听服务 → 停止本次任务的监听
  ↓
代理商监听服务 → POST /api/partner/danmaku/comments (平台)
  参数: msg_type=sys, status=-1
  ↓
平台服务器 → 标记停止并取消重连任务
  ↓
平台服务器 → 返回 {code: 1, msg: "已接收"}
  
[或]

用户 → 关播
  ↓
平台服务器 → POST /api/open/tasks/stop (代理商)
  参数: live_auth_code
  ↓
代理商监听服务 → 停止订阅并清理待发送弹幕
  ↓
代理商监听服务 → 返回 {code: 1, msg: "停止成功"}
```

## 六、重要技术要点

### 6.1 关键约定
1. **live_auth_code 是核心标识**: 平台内部维护 live_auth_code 与直播、房间、用户、代理商的映射关系
2. **代理商不需传递自己的开播位ID**: 只需原样返回 live_auth_code
3. **系统通知通过 msg_type="sys" 识别**: 与普通弹幕使用同一接口推送
4. **msg_id 用于幂等**: 重试时保持不变，防止重复处理
5. **同步响应**: 开始、停止、重连接口均同步返回执行结果

### 6.2 重连逻辑
- 重连命令由平台方服务器发起
- 实际监听连接的建立由代理商完成
- 成功失败遵循同步响应及重试约定，不由平台独立判断状态

### 6.3 msg_type 支持的类型
- `msg`: 普通评论/弹幕
- `come`: 用户进入直播间
- `follow`: 关注主播
- `like`: 点赞/比心
- `gift`: 送礼物
- `sys`: 系统通知（特殊类型）
